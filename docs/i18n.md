# Internationalization

Kurikulum is multi-locale by default. Page bodies, glossary entries, course title, and chrome strings (Submit / Next / Search course content / …) all swap together. Build one ZIP per locale for SCORM distribution, or load every locale into a single dev bundle for live A/B authoring.

## Mental model

Two distinct things are localized:

1. **Content** — page bodies, glossary entries, course title, search index. Lives under `src/content/<locale>/`. Per-locale modules.
2. **Chrome strings** — UI labels rendered by the framework: nav buttons, dialog titles, action labels, ARIA. Lives in flat dictionaries (`Record<key, string>`).

You usually edit (1) heavily and rarely touch (2). Core ships sensible defaults for (2) in Czech and English (`coreDictCs`, `coreDictEn`); override only the keys you want to change.

## Content layout

```
src/content/
  cs/
    index.ts          # exports `title`, `glossary`, `pages`
    pages/
      IntroPage.tsx
      QuizPage.tsx
      …
  en/
    index.ts
    pages/
      …
```

`src/content/<locale>/index.ts` must export:

```ts
import { IntroPage } from './pages/IntroPage.tsx'
import { QuizPage } from './pages/QuizPage.tsx'

export const title = 'Web Security Basics'

export const glossary = [
  { term: 'XSS', definition: 'Cross-site scripting attack…' },
  // …
]

export const pages = {
  intro: IntroPage,
  quiz: QuizPage,
  // page IDs must match `config.pages` in course.tsx
}
```

The `kurikulum()` Vite plugin scans these directories at build time, exposes them as `virtual:kurikulum-content`, and builds a per-locale search index from the page bodies (parsing `<h1>` / `<h2>` for titles).

## Build modes

Controlled by `KURIKULUM_LOCALE`:

| Value           | Behavior                                                                                                                                         |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `auto`          | Loads every locale into the bundle. Dev switcher visible (`<DevLocaleBar>`, Alt+L). Default in `vite serve`.                                     |
| `cs` / `en` / … | Single-locale build — only that locale's content goes into the bundle (tree-shaken). Default in `vite build` is the first locale alphabetically. |

```bash
# Dev — multi-locale, switcher visible:
bun run dev

# Per-locale SCORM zips:
KURIKULUM_LOCALE=cs bun run build:scorm    # → dist/scorm-1.2-cs/ + dist/Course-cs.zip
KURIKULUM_LOCALE=en bun run build:scorm    # → dist/scorm-1.2-en/ + dist/Course-en.zip
```

## Locale detection (runtime)

When the page first loads, `<KurikulumApp>` picks a locale via this chain (the first hit wins):

1. `?lang=…` URL query param
2. `adapter.getLanguagePreference()` — SCORM `cmi.student_preference.language` / `cmi.learner_preference.language`, or `localStorage['kurikulum:locale']` for standalone
3. `navigator.language`
4. `defaultLocale` from `virtual:kurikulum-content`
5. First entry in `available`

Each step's value must be in the `available` list (otherwise it's skipped).

When the user picks a different locale (via `<DevLocaleBar>`, `<LocaleSwitcher>`, or `setLocale()` from `useLocale()`), `<KurikulumApp>` calls `persistLocaleChange` by default — writing back to the adapter and pushing `?lang=…` to the URL via `history.replaceState`. No reload; the component tree re-renders with the new bundle and dictionaries.

## Chrome strings — `useLocale().t(key, vars?)`

Headless components and template wrappers use `t()` for every visible string:

```tsx
import { useLocale } from 'kurikulum'

function MyButton() {
  const { t } = useLocale()
  return <button>{t('actions.submit')}</button> // 'Submit' in en, 'Odeslat' in cs
}

// Variable interpolation:
<p>{t('assess.score', { score: 8, max: 10 })}</p> // 'Score: 8/10'
```

Lookup walks: active locale → fallback locale (`fallbackDictLocale`, default `'en'`) → `coreDictEn` → raw key. In dev mode a missing key logs a warning to the console.

## Default dictionary keys

`coreDictEn` / `coreDictCs` ship with all built-in chrome keys: `nav.*`, `actions.*`, `assess.*`, `audio.*`, `categorySort.*`, `course.*`, `glossary.*`, `matching.*`, `notes.*`, `ordering.*`, `resume.*`, `search.*`, `assessment.aria`. Look at `packages/core/src/i18n/dicts.ts` for the full list.

## Adding more locales / overriding strings

Pass `dictionaries` to `<KurikulumApp>`:

```tsx
import { KurikulumApp } from 'kurikulum/auto'
import { coreDictCs, coreDictEn } from 'kurikulum'

const dictionaries = {
  cs: { ...coreDictCs, 'actions.submit': 'Odeslat odpověď' },  // override one key
  en: coreDictEn,
  de: { /* … your German chrome dict … */ },                   // add a locale
}

<KurikulumApp config={config} dictionaries={dictionaries}>
  …
</KurikulumApp>
```

The `dictionaries` keys must match the `available` list from `virtual:kurikulum-content` (i.e. the locale subdirectories under `src/content/`).

## Locale switcher UI

`<LocaleSwitcher>` is a headless render-prop component you can wrap in your own UI:

```tsx
import { LocaleSwitcher } from 'kurikulum'

<LocaleSwitcher>
  {({ locale, available, setLocale }) => (
    <select value={locale} onChange={(e) => setLocale(e.currentTarget.value)}>
      {available.map((l) => <option key={l} value={l}>{l}</option>)}
    </select>
  )}
</LocaleSwitcher>
```

It returns `null` when only one locale is available (set `alwaysRender` to force).

`<DevLocaleBar>` (in `template/src/components/DevLocaleBar.tsx`) is a styled switcher mounted by `<DefaultLayout>` — visible only when `KURIKULUM_DEV_LOCALE_SWITCHER` is true (i.e. `vite serve` + `auto` mode + ≥2 locales). Press `Alt+L` to cycle.

## Adapter language preference

Optional methods on `DeliveryAdapter`. The built-in adapters implement them:

| Adapter      | Read / Write field                                                    |
| ------------ | --------------------------------------------------------------------- |
| `scorm-1.2`  | `cmi.student_preference.language`                                     |
| `scorm-2004` | `cmi.learner_preference.language`                                     |
| `standalone` | `localStorage['kurikulum:locale']`                                    |
| `xapi`       | unset (no canonical xAPI field; falls through to navigator detection) |

`<KurikulumApp>` reads the preference during initial detection (step 2 above) and writes it back on every `setLocale()` via `persistLocaleChange`. So a learner's choice survives reloads (LMS-stored preferences) or visits (standalone localStorage).

## Per-page text inside content components

The page body components themselves are per-locale (`src/content/cs/pages/IntroPage.tsx` vs `…/en/…`), so all body text is just literal JSX in each locale's source. You don't need `t()` for content text — only for chrome that survives across locales (e.g. a footer button rendered by a template wrapper).

## Disabling i18n for a single-language project

Build with one locale, `dictionaries={undefined}` (default), and don't render `<DevLocaleBar>`. The framework still uses `t()` internally but every key resolves to the default English/Czech default — no surprises, no extra wiring.
